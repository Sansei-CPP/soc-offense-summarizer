# Известные паттерны ложных срабатываний — аутентификация

## Паттерн 1: Сканеры уязвимостей

Внутренние security-сканеры (Nessus, Qualys, Tenable) часто генерируют
события неудачной аутентификации. Source IP обычно находится в
задокументированном диапазоне сканера. Подтвердить у клиента перед
закрытием.

## Паттерн 2: Некорректно настроенные сервисные аккаунты

Сервисные аккаунты с истёкшими или ротированными учётными данными
генерируют непрерывные события неудачной аутентификации. Паттерн:
одно имя пользователя, один источник, продолжается часами или сутками.
Как правило, не брутфорс — нет вариации имён пользователей.

## Паттерн 3: Плановые задания резервного копирования

Backup-агенты, аутентифицирующиеся на удалённые хосты, могут временно
давать сбой в период ротации учётных данных. Сверить время событий с
расписанием обслуживания.

## Паттерн 4: Health checks балансировщика нагрузки

Некоторые конфигурации балансировщика выполняют TCP health checks на
SSH/RDP-порты, генерируя события соединений, похожие на auth failures.
Source будет внутренним IP из инфраструктурного диапазона.

## Ни один из паттернов не применим если

- Источник внешний / маршрутизируемый из интернета
- В той же сессии произошла хотя бы одна успешная аутентификация
- Target является критическим активом по классификации
